# 日通 POC｜關鍵待釐清問題

- 更新日期：2026-08-10
- 用途：會後內部對焦與後續客戶確認
- 原則：區分已確認方向、Prototype 工作假設與仍會改變 POC 流程的關鍵問題

## 1. 本次會議已確認

| 主題 | 已確認內容 | Prototype 對應調整 |
|---|---|---|
| 角色分工 | 建立他向業務訂單與安排調度為不同角色；調度從「待插單」清單接續安排 | 「待插單」維持獨立工作入口，不視為時間軸的附屬功能 |
| 原規劃比較 | 調度需要直接比較原規劃與目前執行情況 | 「顯示原規劃」預設開啟 |
| 異常邏輯 | 「可能延遲」不是獨立異常，而是某站點已延遲後，對後續行程的連帶提醒 | 總覽統一為「異常」；車輛以紅色 Warning 提示「後續 N 個站點可能延遲」；不另設可能延遲任務或篩選 |
| 車輛使用方式 | 固定牛奶便與他向業務通常使用不同車輛 | 插單主流程不再預設一定要插入牛奶便車輛；牛奶便車輛支援他向業務視為較特殊情境 |

## 2. 先跟內部對齊

| ID | 關鍵問題 | 目前方向 | 需要的結論 |
|---|---|---|---|
| I-01 | POC 最終要證明什麼？ | 讓調度在單一畫面掌握 91 台車的進度與可用狀況，快速找出異常及他向業務可用車輛，提高車輛有效利用率 | 成功判準，以及監控、異常與他向業務安排的優先順序 |
| I-02 | 這版 Prototype 是內部討論稿，還是可直接作為客戶提案？ | 先作為需求釐清工具，畫面不代表排車規則與演算法已確認 | 展示對象、資料真實度與需要完成的驗證情境 |

## 3. 需要跟客戶確認

| ID | 主題 | 關鍵問題 | Prototype 暫定方向 | 為何會影響設計 |
|---|---|---|---|---|
| C-01 | 整體／監控 | 監控主體以「車輛」為主是否合理，現有車牌、司機、路線、便次、站點與時間是否足夠？ | 一列一台車，以時間軸掌握任務與異常，地圖按需展開 | 決定看板列結構、辨識資訊與篩選方式 |
| C-02 | 插單邏輯／車輛與司機 | 安排他向業務時，是由調度直接選擇車輛與司機，還是由系統先提示目前有空檔的車輛／司機？ | 系統呈現可用車輛及既有任務，最後由調度決策，不自動指派 | 決定流程入口、候選生成方式，以及車輛與司機是否需要分開選擇 |
| C-03 | 插單邏輯／後續影響 | 若車輛或司機支援他向業務後，稍晚仍有原定行程，如何判斷是否會影響後續任務或發生「掉棒」？ | 候選需同時揭露目前空檔、後續任務、司機排班與可能受影響的行程 | 決定硬限制、影響提示、交班處理與是否允許確認安排 |
| C-04 | 異常告警 | 已延遲後，系統如何判斷後續哪些站點可能受影響？還需要掌握哪些其他異常？ | 已延遲站點維持站點層級資訊；車輛層級彙整後續受影響站點數 | 需確認資料來源、計算規則、解除條件，以及未出車、異常停留、偏離路線、GPS 中斷等項目的 POC 優先級 |
| C-05 | 地圖／距離 | 車輛與目標站點的距離資訊，應用於日常定位還是他向業務候選比較？ | 先顯示直線距離，僅供初步比較 | 需確認目標站點定義，以及是否必須改成道路距離或預估行駛時間 |
| C-06 | 歷史紀錄 | 客戶對「歷史紀錄」最主要的使用情境是什麼？ | 第一版尚未設計 | 需確認是追查異常、回放路徑與時間、查詢車輛／司機／便次，或製作績效報表 |

## 4. 目前 Prototype 工作假設

以下僅用於推進討論，尚不能視為客戶已確認需求。

| 主題 | 目前假設 | 待驗證方式 |
|---|---|---|
| 主視圖 | 以車輛時間軸為主，地圖按需展開；原規劃預設顯示 | 請調度用 Prototype 找出一台異常車並說明判斷過程 |
| 異常 | 總覽只保留「異常」；已延遲站點顯示延遲時間，車輛彙整提示後續 N 個站點可能延遲 | 用真實延遲案例確認影響站點數與解除時機 |
| 他向業務入口 | 「待插單」為調度角色的獨立工作入口 | 驗證調度是否能清楚察覺新訂單並進入安排流程 |
| 候選方式 | 優先呈現有可用空檔的車輛／司機，由調度比較後決策 | 請調度說明實際選車、選司機的順序與必要資訊 |
| 特殊支援 | 牛奶便車輛承接他向業務時，需額外檢查後續任務、交班與掉棒風險 | 以一筆會影響後續行程的極端案例驗證 |
| 歷史紀錄 | 不納入第一版 Prototype | 先確認核心使用情境後再決定頁面結構 |

## 5. 下一次討論最少要得到的答案

- [ ] 車輛與任務的辨識資訊是否足夠。
- [ ] 他向業務安排時，車輛與司機由誰選擇，系統需要提示到什麼程度。
- [ ] 「可用空檔」的判斷條件，以及如何檢查後續任務與掉棒風險。
- [ ] 已延遲如何推導後續受影響站點數，還有哪些異常必須納入 POC。
- [ ] 歷史紀錄最重要的使用情境，以及是否納入本輪 POC。
