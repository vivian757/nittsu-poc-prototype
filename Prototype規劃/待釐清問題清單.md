# 日通 POC｜關鍵待釐清問題

- 更新日期：2026-08-12
- 用途：整理會影響 POC 資訊架構、判斷規則與操作流程的關鍵問題
- 原則：先列待釐清問題與 Prototype 假設，已確認內容集中放在文件最下方

## 1. 先跟內部對齊

| ID | 關鍵問題 | 需要的結論 |
|---|---|---|
| I-01 | POC 最終要證明什麼？ | 明確定義成功指標，例如調度找出異常、完成他向業務指派所需的時間與步驟 |
| I-02 | POC 要驗證到介面流程、規則計算，還是實際資料串接？ | 確認技術驗證範圍、模擬與正式資料的邊界，以及歷史功能是否納入本輪 |

## 2. 待釐清

| ID | 主題 | 關鍵問題 | 影響範圍 |
|---|---|---|---|
| C-01 | 營運監控 | 以車輛為主體是否符合調度習慣？車牌、當前司機、客戶／路線、便次、站點與時間是否足以辨識任務？「執行中、目前空檔、異常」的分類與排序是否符合日常查看順序？ | 固定欄資訊、車輛排序、篩選與主畫面層級 |
| C-02 | 時間差判斷 | **過往 TMS 專案經驗提醒（非日通現行系統規則）**：當時電子圍籬判斷會設定緩衝容許時間，並以單一時間欄位產生「提早、準時、延遲」其中一個狀態；即使規則較單純，仍花費許多時間釐清。本案已確認抵達與離站都要掌握，因此更需先確認：哪個時間決定任務的唯一主狀態？另一個時間差是次要資訊，還是也會影響狀態？提早抵達但延遲離站時如何判定？ | 狀態模型、顏色、異常計數與電子圍籬規則；過往經驗僅作為釐清風險提醒，不代表客戶需求或目前系統邏輯 |
| C-03 | 異常 Filter | 「異常」要整合哪些狀況？目前是否只收斂為當前任務延遲，或也包含未出車、異常停留、偏離路線、GPS 中斷與任務未回報？計數單位是車輛還是任務？ | Filter 數字、車輛層級提醒、異常詳情與處置入口 |
| C-04 | 牛奶便／他向業務車輛 | 他向業務車與牛奶便固定車是否為完全分開的車池？是否存在臨時共用、跨時段接續或其他例外？ | 可用車輛範圍、時間軸資料、車輛空檔與候選邏輯 |
| C-06 | 他向業務指派 | 是否確認採「先找符合技能與工時的司機空檔，再搭配可用車輛」？系統要自動篩出候選、只提示衝突，還是保留完全人工指定？任務預估時間、技能、工時、前後任務緩衝與車輛條件如何計算？ | 指派順序、候選生成、不可指派原因與預覽內容 |
| C-07 | 後續任務銜接不足 | 銜接時間不足的門檻如何計算？應在確認前阻擋／提醒，還是先完成指派後再提醒？變更下一任務司機時，是否需要重新檢查工時、空檔與後續連鎖衝突？ | 警示時機、Dialog 流程、改派範圍與排程寫入方式 |
| C-08 | 時間軸／空檔定義 | 目前「空檔」只表示兩個任務區段之間的時間，不包含車輛從前一站行駛至下一站所需的時間。這段任務間空白是否能直接視為可指派空檔？正式判斷時是否需扣除前後行駛與銜接時間？ | 空檔長度、候選資格、時間軸提示，以及插單後是否能準時銜接前後任務 |

## 3. 目前 Prototype 工作假設

以下方向已用於 Prototype，但在上述規則確認前，不代表正式產品規格。

- 以車輛時間軸為營運監控主視圖，地圖按情境展開。
- 原規劃是主要基準；實際執行預設顯示，抵達與離站時間差放在次要視覺與 Hover 詳情。
- 每個站點仍應只有一個主要狀態；抵達與離站如何合併判斷，暫不視為已定案。
- 「異常」暫以車輛當前最新任務延遲彙整，後續影響顯示在車輛層級。
- 他向業務暫採先選司機空檔、再搭配非固定便次車輛；系統提供候選但不標示最佳推薦。
- 時間軸上的「空檔」暫只依任務起訖時間計算，尚未納入前後站點的行駛時間。
- 他向業務暫視為同一張訂單由同一位司機完成取貨與到貨，待確認是否允許拆單或中途交接。
- 後續任務銜接不足暫採「先完成本次指派，再提醒是否變更下一任務指派」。

## 4. 已釐清

| 主題 | 已確認內容 | Prototype 對應 |
|---|---|---|
| 角色分工 | 建立他向業務訂單與調度指派為不同角色；調度從「待插單」清單接續安排 | 「待插單」為獨立工作入口，不視為時間軸附屬功能 |
| 客戶現況 | 客戶目前沒有實際使用電子看板；現有系統廠商「天眼」曾提供示意圖，但未落地使用 | Prototype 是需求與提案方向的驗證工具，不應描述成既有流程的直接改版 |
| 時間差基礎 | 時間差主要針對牛奶便；每一趟次都有原規劃開始與結束時間，並以電子圍籬進／離場事件取得實際時間 | 原規劃為基準，實際執行呈現抵達與離站資訊 |
| 抵達與離站 | 抵達時間差與離站時間差都需要掌握；但兩者如何形成任務唯一主狀態仍待釐清 | 主時間軸簡化呈現，完整差異放在 Hover 詳情 |
| 時間軸結構 | 站點區塊代表原規劃；站點間空白即為行駛區間，不需另畫行駛任務；實際執行不會超過現在時間 | 「顯示實際狀況」預設開啟，實際線疊在原規劃下方 |
| ETA 可能延遲 | 經 ETA 判定為可能延遲的站點，時間軸任務區塊整塊使用淺橘色呈現 | 與已發生延遲的紅色狀態區隔，並保留文字或圖示輔助辨識 |
| 地圖使用時機 | 調度會在臨時訂單、司機回報狀況、客戶反映尚未看到車，以及直覺察覺異常時查看定位 | 時間軸維持主視圖，地圖由車輛、站點或訂單入口按需定位 |
| 牛奶便固定車 | 原牛奶便使用的固定車輛原則上不更換，可能涉及載貨及工廠需預先掌握車牌 | 他向業務不會直接改動原牛奶便車輛的安排 |
| 司機空檔 | 司機空檔是兩個任務間可承接本單的時段；上下任務皆無屬於當日未排班，不稱為空檔 | 空檔卡顯示上一任務、下一任務、預估工時與車輛選單 |
| 指派預覽 | 選司機時聚焦其時段；選完車輛後才切換至該車輛並顯示站點預覽；更換司機會清除已選車輛與預覽 | 指定時段、司機空檔與站點預覽分層呈現 |
| 銜接提醒 Prototype 方向 | 確認指派完成後先顯示成功訊息；若下一任務銜接不足，再以 Dialog 引導使用者前往變更指派 | Snackbar「已指派，排程已更新」後顯示銜接不足 Dialog |
