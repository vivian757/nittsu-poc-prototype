## 3. 目前 Prototype 工作假設

以下方向已用於 Prototype，但在上述規則確認前，不代表正式產品規格。

- 以車輛時間軸為營運監控主視圖，地圖按情境展開。
- 大螢幕優先顯示異常與延遲分鐘；個人電腦承接細節及處理操作。
- 原規劃是主要基準；實際執行預設顯示，抵達與離站時間差放在次要視覺與 Hover 詳情。
- 「異常」目前只納入車輛當前最新任務的延遲；其他異常類型尚未納入。
- 他向業務暫採先選司機空檔、再搭配非固定便次車輛；系統提供候選但不標示最佳推薦。
- 時間軸上的「空檔」暫只依任務起訖時間計算，尚未納入前後站點的行駛時間。
- 後續任務銜接不足採「先完成本次指派，再提醒是否變更真正無法銜接的單一完整便次」。
- 車輛需區分定點停留與站點間移動；跨日資料依執行日切分。
- 點呼表第一版忠實數位化紙本，不先擴張動態預警；目前以固定報到地點、共用電腦／帳號及手動填寫點檢者為 Prototype 工作假設。
- POC 優先使用 D-4，國瑞特殊時間欄位先轉換；第一版兩台車機先集中牛奶便。

## 4. 已釐清／Prototype 已收斂

| 主題 | 已確認內容 | Prototype 對應 |
|---|---|---|
| 角色分工 | 建立他向業務訂單與調度指派為不同角色；調度從「待插單」清單接續安排 | 「待插單」為獨立工作入口，不視為時間軸附屬功能 |
| 客戶現況 | 客戶目前沒有實際使用電子看板；現有系統廠商「天眼」曾提供示意圖，但未落地使用 | Prototype 是需求與提案方向的驗證工具，不應描述成既有流程的直接改版 |
| 時間差基礎 | 時間差主要針對牛奶便；每一趟次都有原規劃開始與結束時間，並以電子圍籬進／離場事件取得實際時間 | 原規劃為基準，實際執行呈現抵達與離站資訊 |
| 抵達與離站 | 抵達與離站時間差都需要掌握；Bar 顏色以最新已發生事件為主：尚未離站時看抵達狀態，離站後改以離站狀態呈現；準時不需在資訊卡重複列出 | 主時間軸顯示目前最新狀態，Hover 僅補充提早或延遲的抵達／離站差異 |
| 營運監控排序 | 總覽中的車輛依「異常 → 執行中 → 其他」排序；牛奶便車輛排在他向業務車輛之前，無當前任務的車輛置底 | 主畫面先呈現需介入與正在執行的車輛，降低調度掃描成本 |
| 大螢幕與個人電腦 | 大螢幕不用操作即可看出異常；個人電腦用於查看細節與處理，兩者資訊密度可不同 | 大螢幕強化異常、延遲分鐘與狀態層級；個人電腦保留完整時間軸與操作 |
| 異常收錄規則 | 當前最新執行的任務站點有延遲才列入異常；若最新離站為準時或提早，則不納入異常。後續站點的 ETA 風險另以「可能延遲」呈現，不等同已發生延遲 | 異常 Filter 聚焦已發生且仍影響當前行程的延遲；ETA 使用淺橘色預警 |
| 時間軸結構 | 站點區塊代表原規劃；站點間空白即為行駛區間，不需另畫行駛任務；實際執行不會超過現在時間 | 「顯示實際狀況」預設開啟，實際線疊在原規劃下方 |
| 車輛移動狀態 | 車輛需區分定點停留與站點間移動，避免離站後仍像停在上一站 | 時間軸與定位資訊顯示正在前往的下一站；移動中車輛 Icon Tooltip 統一使用「前往下一站」 |
| ETA 可能延遲 | 經 ETA 判定為可能延遲的站點，時間軸任務區塊整塊使用淺橘色呈現 | 與已發生延遲的紅色狀態區隔，並保留文字或圖示輔助辨識 |
| 地圖使用時機 | 調度會在臨時訂單、司機回報狀況、客戶反映尚未看到車，以及直覺察覺異常時查看定位 | 時間軸維持主視圖，地圖由車輛、站點或訂單入口按需定位 |
| 兩種業務的指派單位 | 牛奶便的資料層級為「固定車輛 → 便次 → 多個站點」，司機綁定整個便次；他向業務則由司機、車輛綁定單筆訂單，沒有便次概念 | 牛奶便以便次為改派單位；他向業務維持單筆訂單指派，時間軸資訊以「他向業務＋客戶名稱」辨識 |
| 牛奶便固定車 | 原牛奶便使用的固定車輛不提供更換，可能涉及載貨及工廠需預先掌握車牌 | 變更牛奶便指派時只更換司機，車輛唯讀；他向業務插單不直接改動牛奶便車輛 |
| 牛奶便便次結構 | 同一路線不同便次原則上重複相同站點組合，站點停留與站間時間固定或接近；便次間保留該路線相對固定的空檔 | 時間軸以成組且重複的站點呈現各便次，避免任務重疊或分布過度平均 |
| 牛奶便一般改派 | 點擊任一站點只是操作入口，實際變更該站點所屬便次的司機，並同步套用便次內全部站點；已完成便次不可改派，執行中便次需另走交接／異常流程 | 時間軸 Highlight 整個便次；Panel 顯示路線、便次、完整時段、站點數、固定車輛與目前司機，確認後一次更新整個便次 |
| 牛奶便可指派司機 | 變更牛奶便指派時，候選先從當日跑他向業務的司機中篩選，且該司機必須能完整承接目標便次；不以單一站點可用作為判斷 | 「可指派司機」只列出他向業務司機並提供查看其既有時間軸；預覽不改寫時間軸左側目前司機或 Hover 司機，確認後才正式更新 |
| 司機空檔 | 司機空檔可位於兩個任務之間，也可位於當日最後一個任務後方；上下任務皆無屬於當日未排班，不稱為空檔。沒有下一任務時可能代表已下班，需顯示今日工時並視為加班候選 | 空檔卡顯示上一任務、下一任務與報到／今日工時資訊，再搭配可用車輛 |
| 插單候選空檔 | 系統以訂單實際工時在指定時段內尋找可容納的起始時間，不要求整個指定時段皆無任務；前後兩側共用監控設定的「任務銜接最小間隔」，Prototype 預設 30 分鐘。低於門檻仍列入候選並顯示警示，與下一任務時間重疊才不納入候選 | 同時掃描值班司機與可用他向業務車輛；最後一個便次後若無下一任務仍可列為加班候選 |
| 指派預覽 | 選司機時聚焦其時段；選完車輛後才切換至該車輛並顯示站點預覽；更換司機會清除已選車輛與預覽 | 指定時段、司機空檔與站點預覽分層呈現 |
| 插單後單一便次改派 | 插單先獨立完成；若造成牛奶便銜接不足，只轉移真正無法銜接的完整便次，便次內可有多個站點；原司機保留其他未受影響的後續便次 | 成功 Snackbar 後保留「插單後任務銜接時間不足」Dialog；點擊「變更指派」後自動聚焦受影響車輛列與完整便次；「稍後處理」只關閉提醒，不建立待辦，之後仍可從該便次任一未開始站點重新進入；確認後只更新該完整便次 |
| 兩種 ETA 模式 | 前一任務延遲且尚未結束時，先以前站遲到時間、原定作業時間及後續移動時間推估；取得實際離站時間後再重算 | 後續站點標示「尚未離站推估」或「實際離站後重算」，並維持淺橘色風險與紅色已發生延遲的區隔 |
| 實際執行時間邊界 | 實際執行資料只代表已發生事實，不會出現在「現在」右側；進行中的實際線最多貼齊現在 | 時間軸以現在線截斷實際執行，不把未來預估混入實際線 |
| 點呼表資料單位與角色 | 同一天一位司機只會有一筆點呼表紀錄；目前假設司機到固定地點報到，由現場點檢者透過共用電腦／帳號執行作業前／後點呼，點檢者姓名以純文字 Input 填寫，不由登入帳號推定 | 未報到時只顯示「報到」；報到後可由時間右側鉛筆 Icon 更正，不保留修改紀錄；未報到不可編輯或點檢，本輪不加入另一層審核角色 |
| 點呼表首版方向 | 第一版先忠實完成紙本欄位、填寫、儲存與點檢，不先加入動態預警 | 現有欄位及狀態為 Prototype 示意；事後抽查／稽核不納入本輪流程 |
| 跨日與資料匯入 | 跨日回載依執行日切分；POC 優先使用 D-4，國瑞特殊時間欄位先轉換 | 匯入前進行版本辨識與欄位 Mapping；正式跨日邊界仍列待確認 |
| 車機測試範圍 | 第一版兩台車機先集中牛奶便 | 以兩台車機驗證欄位、更新頻率及 ETA／移動狀態資料可用性 |
